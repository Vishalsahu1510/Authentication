const otp = Math.floor(100000 + Math.random() * 900000).toString();

Math.random() is NOT cryptographically secure.

Why this matters

OTPs are security-sensitive

Math.random() can be predictable

Vulnerable to brute-force or prediction attacks

For password reset, login, or email verification, this is not safe enough.


✅ Use crypto.randomInt (BEST)
import { randomInt } from "crypto";

const otp = randomInt(100000, 1000000).toString();

Why this is better

✔ Cryptographically secure
✔ Uniform distribution
✔ Same 6-digit guarantee
✔ Built into Node.js


🔐 Another secure option
import { randomBytes } from "crypto";

const otp = (parseInt(randomBytes(3).toString("hex"), 16) % 900000 + 100000).toString();


But randomInt is cleaner and safer.

Best practice OTP checklist

✔ Use cryptographically secure randomness
✔ Store OTP hashed in DB/Redis
✔ Set TTL (5–10 minutes)
✔ Limit attempts (rate-limit)
✔ Invalidate after use
